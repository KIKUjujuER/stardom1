A release with a **feature** and four **fixes**: a hardware keyboard finally
reaches the emulator, the app can start DOSBox again instead of dying, the
tone that rode on the music is gone, and **Game Mode** comes back the way you
left it.

* **A Bluetooth keyboard works.** The vendored SDL2 has no path for Android key
  events, so the Java layer fed only the IME and the native side never saw a
  single key: a key pressed on a Bluetooth keyboard — or injected with
  `adb shell input keyevent` — never reached the emulator, and the on-screen
  keyboard was the only input there was. The app now maps an Android key code
  to a DOSBox key name and resolves it through the same native table the
  on-screen keyboard uses, so both end in exactly the same scancode. **Shift,
  Ctrl and Alt** are carried along, so DOS sees the capital letters it should.
  Only the first press of a held key is forwarded — DOSBox does its own
  auto-repeat in the BIOS timer, and every extra event would be one more
  scancode in the BIOS buffer. A keystroke aimed at the launch-script editor
  still never reaches the game. Checked in the emulator with real key events:
  the letters and **Enter** pass the copy protection of *Mortal Kombat*,
  **F1** starts the game, **F10** opens its own options menu, and the arrow
  keys move the menu cursor and are accepted as the game's movement keys.
* **DOSBox can start again in the same app run.** The device table is a static
  array of ten slots, and the devices of a run were never removed from it, so
  a second start in the same process — the app keeps its process alive between
  two starts — ran out of slots and died with *DOS:Too many devices added*.
  Leaving the app with the Back button and opening it again was enough to hit
  it. The devices of the DOS section are now removed when it shuts down.
* **The tone that rode on the music is gone.** A steady beat tone sat on top of
  the in-game music on a real phone, and only while the music played — the
  digital sound effects, being transient, stayed clean. DOSBox keeps its audio
  buffer centred by continuously re-tuning the emulator's effective output
  sample rate, and under the steady, heavy load of OPL/FM synthesis on a phone
  that control loop hunts; because a held FM note is a sustained carrier, the
  hunting frequency-modulates it into an audible warble. The shipped
  `dosbox.conf` now runs the mixer the way a phone wants it: at the device's
  native **48 kHz**, in blocks of **2048**, with a **50 ms** prebuffer. This
  changes audio buffering only — never game speed or logic — and costs about
  50 ms of latency, which is inaudible in a DOS game. The whole analysis, with
  the three diagrams of the pipeline, the control loop and the modulation, is
  in `docs/AUDIO-FM-BEEP.md`.
* **Game Mode comes back the way you left it.** The profile, the D-pad mode
  and the remaps are restored in one pass, before the gamepad is built. The
  D-pad has to be in place before the bar is built, or the chip that names the
  mode would name the previous one — the separate setters had to be called in
  an order the caller could get wrong, and one layout pass cannot.
* **The TURBO auto-fire cannot get stuck.** While the FIRE button is held, the
  TURBO chip fires it again and again. The loop lived in the button's own
  touch listener, and a rebuild — a rotation, or the other thumb cycling a
  chip — detached that view mid-hold without an `ACTION_UP`, so the listener
  never stopped and the key fired forever. The loop now lives with the game
  pad, and every path that releases the keys cancels it.

The **user guide** grew with it: the keyboard's **columns layout** — the one
key column per side that the app falls back to when the black bar beside the
4:3 picture drops below 116 dp — is now pictured, and so is the narrow-screen
keyboard, squeezed to about 24 dp letters in an 18:9 frame. The new **Game
Mode** screenshots were re-taken from the 1.0.0.17 release build, so the
frames in the guide, in the repository and in the capture set are the same
ones. The dead *SEE ALSO* section is out of the DOSBox man page, the remap
outline is checked on the device in pixels, and the checksum of the shipped
1.0.0.17 APK is recorded in the repository.

The save states, the bundle launcher, the on-screen keyboard and the emulator
core are unchanged: **every save state written by the earlier releases loads
normally**.
