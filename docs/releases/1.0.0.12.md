This is a **patch** release on top of the `android-migration-complete`
milestone. The mouse work that closed the Android migration phase — the
**RMB** key on the left pad next to **Tab**, the second-finger right click,
and the INT 33h mouse state in the save file — is what 1.0.0.11 shipped, and
the picture above is that release. The milestone marker moves on to this
release.

What this release repairs is the packaging around that work, and one thing in
it that was wrong.

* **The save state no longer restores the mouse driver's volatile half.**
  1.0.0.11 put the *whole* INT 33h driver into the snapshot, including the
  event queue, the click counters and the interrupt re-entrancy flags.
  Restoring that wedged mouse-driven games: the stale queue and flags fed
  garbage into the INT 74 handler and into the game's own callback, and a
  game could hang on load. The snapshot now carries only the stable
  configuration — the game's event-callback registration, the cursor range and
  the cursor position — and the volatile state is left clean, so a restored
  game starts from an idle driver.
* **The native library knows its own version.** The version was a literal
  `1.0.0.1` in the Android config template, so the emulator reported
  *WhereQ-DOSBox version 1.0.0.1* in the DOS startup banner and in the window
  title no matter which release was installed, the BIOS machine string said
  1.0.0.1, and the mapper file was always `mapper-1.0.0.1.map`. The native
  build now reads the same `VERSION` file that the release script writes and
  the Gradle build reads, so the version in the banner and the version on the
  downloads page can no longer disagree.
* **A local build ships all three ABIs.** `android/build-android.sh` and
  `android/build-sdl2.sh` defaulted to two of them, so an APK built from a
  plain `./bin/build.sh apk` did not carry the same ABI set as the published
  one. Both now build `arm64-v8a`, `armeabi-v7a` and `x86_64` by default — the
  same set CI builds and the same set this release carries.

**Save states written by 1.0.0.11 and by the first 1.0.0.12 cannot be loaded
by this build.** The state file grew a version when the mouse block was
slimmed, and an older state is refused rather than misread. Save states
written by this build load normally.

One consequence of the slimmed block: the button state is no longer captured,
so a restored game starts with the mouse released and a click that was held
down across the save has to be pressed again.

One thing to know: the mapper file is named after the version, so it is
`mapper-1.0.0.12.map` now. A hand-made `mapper-1.0.0.1.map` is not picked up
any more — rename it if you had one.
